## 1. What this is

**Name (engineer, 2026-10-07):** the app is **Northrop Hardhat** ("Hardhat" under its home-screen icon). Its icon is the Northrop roundel (red, on white) whose white N wears a white hard hat (`public/icon.svg`, the N from Figtree Bold; `npm run icons:build` makes the PNGs). The side rail keeps the plain Northrop N.

An iPad-first, offline-capable inspection companion for a structural engineer. On site the engineer opens the drawing PDF, drops lettered markers on the areas of concern, attaches photos, writes instructions, and the app generates a **Site Instruction Memo** (editable in-app, exported as a single PDF) with the marked-up drawing and a photo appendix attached.

Longer term the app also holds engineering calculators (AS 3600) and a standard details library. These are **separate areas of the app**, independent of the inspection and memo workflow, and are **not** part of the first build.

## 2. Users and context

- **Primary user:** one structural engineer, on site, on an iPad (Apple Pencil available), with patchy internet.
- **Secondary:** same engineer at a desktop, to review and edit a memo before sending.
- **Proof of concept audience:** the company's digital innovation team. They need to open it via a link with no App Store process.
- **Out of scope for the POC:** multi-user accounts, cloud sync, permissions, client-facing access.

## 3. Scope

### Slice 1 (the POC core, build first)
1. Create an inspection (job details).
2. Upload one or more drawing PDFs and view them with smooth pan/zoom.
3. Use **Add pin** to drop **lettered pins** (A, B, C... for instructions and, separately, for observations) on a drawing. Each pin is either an **instruction** or an **observation**, with text, optional photos, and (for instructions) a flag for "photo confirmation required before proceeding".
4. Generate the **Site Instruction Memo**, editable in app.
5. Export one PDF pack: memo + marked-up drawing page(s) + photo appendix.
6. Export/import an **inspection file** so work moves between iPad and desktop.

### Slice 2
Freehand Apple Pencil markup, shapes/clouds/arrows, text callouts, and saving annotated drawings.

### Slice 3
A standalone **Calculators** area of the app (its own top-level section and navigation entry): AS 3600 concrete checks, area of steel, development length, lap length. Calculators do **not** appear in the memo or the PDF export pack, and are not attached to an inspection. Optional on-device history of recent calculations, kept separate from inspection data and not included in inspection files.

### Slice 4
Standard details library (searchable, attachable to a memo item).

## 5. Lettered items and pins

- **Instructions and observations are lettered separately**, each in **document order**: by drawing (the order drawings were added), then page, then the item's order on that page (the order the pins were placed, unless the engineer reorders them in the Items tab). Instructions run A, B, C ... Z, then AA, AB ..., and observations A, B, C ... the same way. So a pin added later on an earlier page takes its place in the sequence and the pins after it move along (pin on page 2 is A; a new pin on page 1 becomes A and page 2's becomes B). An instruction A and an observation A can both exist; they are told apart by pin colour, and the app always names the kind ("Instruction A", "Observation A"). Deleting an item (or a drawing) re-letters the remaining items of that kind so there are no gaps: delete instruction C and instruction D becomes C. Switching an item's kind moves it to the other sequence (at its document-order position) and re-letters both. Memos are checked before sending. After the PDF pack has been exported, a change of letters (an item added, deleted, switched or reordered) shows a short notice over the drawing, once per export, and the Export card lists what changed (e.g. "Instruction B is now Instruction A") until it is exported again; deletes stay instant and undoable, with no confirm (decided 2026-10-04).
- Letters are **per inspection**, not per drawing, so instruction "C" in the memo points to exactly one pin on one drawing.
- The memo's conditions list is generated from the items, e.g. "A. [instruction]". The engineer can edit the text in the memo without changing the underlying item.
- Each item has a **kind**: `instruction` (something the builder must fix or complete) or `observation` (neutral note, no action required). Both get a letter and a pin.
- In the memo, instructions feed the "Ok to proceed subject to the following:" list.
- Observations **do not appear in the memo**, so they are never read as conditions. Instead each drawing page that has pins gets an **observations box** (the "notes box" in the app), burned into that page in the export. It also lists that page's instructions, so the builder sees both on the drawing:
  - A header line on every page with pins: `NORTHROP INSPECTION | {item inspected} | {first initial}. {surname} | {DD/MM/YYYY}` (inspector and date from the inspection; empty parts are left out).
  - Then, only when the page has observations: a heading from a `heading` snippet (default "Noted for information:"; longer alternative in the starter set), followed by that page's observations by letter, e.g. "A. Existing crack noted at grid 4".
  - Then, only when the page has instructions: the fixed heading "Instructions:" followed by that page's instructions by letter, e.g. "A. Add N12 bar at grid C/4".
  - The engineer **drags the box into place** in the drawing viewer so it doesn't cover drawing detail. Its position is stored in normalised page coordinates (0..1), like pins. Default spot: top right of the page, 15 mm in from the top and right edges on every sheet size (just inside a standard 10 mm drawing frame, roughly in line with the title block's right edge).
  - Text size and box width are relative to page size, like the markers, so it stays legible on A1/A3 sheets. In the viewer the box is drawn on the page so it looks as it will in the export.
  - The box is removed from a page when its last pin is removed.
  - Style: header line in black; border and observations in markup blue `#0165FC`; the instructions heading and lines in red `#DA1A32` to match the instruction pins. All in capitals, Arial on screen. The PDF export uses Helvetica (Arial's metric twin, built into every PDF viewer) so no font file is bundled. Colour and fonts live in `src/brand/northrop.ts` (`markup`).
- **Item sheet:** placing a pin creates an item and opens its sheet. New items start as **instruction** with the cursor in the text box; an Instruction | Observation switch changes the kind at any time. Instructions have the "photo confirmation required before proceeding" option. Switching the kind is undoable. Text saves as you type. Tapping a pin reopens its sheet; tapping the drawing away from pins closes it (the text is saved), and a further tap closes the Items or Drawings panel; with nothing open, a tap places a new pin (see the gesture model below). A **Done** button sits above **Delete** (as well as the one in the sheet's header). Delete removes the item at once, with no confirm; Undo brings it back.
- **Pin style:** instructions are filled red circles with a white letter; observations are filled markup-blue (`#0165FC`) circles with a white letter.
- **Arrows:** a pin can have several arrows pointing from it to the spots it refers to, on the same page. A pin can be placed with an arrow in one go (tap, hold, drag; see the gesture model), or in the item sheet, **Add arrow** then tap the drawing where it should point (a tap on another page is refused with a hint). When the item is selected, each arrow's tip shows a hollow handle: drag it to move the tip, tap it to select it, then **Remove arrow** (with a single arrow it needs no selecting). Arrows are a line from the pin with an arrowhead on the spot, in the pin's colour; since 2026-10-06 (engineer) a **dog leg**, drafting style: a horizontal shoulder out of the pin's side facing the spot (its elbow two PDF pin widths beyond the pin's edge, 4% of the sheet's short side from its centre), then straight to the spot, with a straight line when the spot is above or below the pin (within the shoulder); the arrow is sized relative to the page (about 4 pt line and a 30 pt head on A1) and drawn in page units so they zoom with the drawing; the step 8 export burns them in with the same geometry (`src/features/drawings/arrows.ts`). Adding, moving and removing arrows is undoable.
- Letters are always derived from the items and drawings (no stored counter); a new pin starts as an instruction lettered by its place in the document.
- **Copy pin (decided 2026-10-05):** one comment can be pinned at several spots, on any page or drawing. In the item sheet, **Copy pin** stays on (a dark hint at the top right says "Tap each spot for a copy of Instruction A", with **Done**, and the sheet shows **Done copying**) and each tap on the drawing pins the same item again. Every copy is the same item: same letter, text, kind, photo confirmation and photos, so editing the text or switching the kind changes every pin. The **original pin decides the letter**; copies never re-letter anything, so a copy can sit on a page among later letters (the notes box lists items in letter order). Each copy has its own arrows (Add arrow goes to the item's pin on the tapped page, the nearest if there are several) and can be dragged on its own. The sheet lists the item's pins ("Page 1 (original)", "Page 4"…): tap one to go to it, **Remove** takes away just that pin (undoable). Removing the original makes the first copy in document order the original, which can change letters. **Delete** removes the item and every pin. Placing and removing copies are undoable; moving a copy isn't (like pins). A page with only a copy counts as having pins (its notes box lists the item; it can't be hidden), the Items panel lists the item once under its original's page with "N pins", the memo lists it once, the PDF pack burns in every copy, and its photos appear once in the appendix. Copies move with duplicated and moved pages; deleting a drawing removes the copies on it, and an item whose original was on it carries on from its first copy elsewhere.
- In the viewer's Items panel, items are grouped under an **Observations** heading (A, B ...) and then an **Instructions** heading (A, B ...), matching the notes box.
- **General notes (engineer, 2026-10-07):** **Add general note** at the top of the Items panel adds an observation with **no pin**, for something that belongs to the whole inspection rather than a spot (e.g. "Inspection limited to the roof, grids 1–4 / A–C"). General notes are always observations (never instructions, so never in the memo), are lettered **first** (A, B …) with the pinned observations following on, and are listed in **every page's notes box**, before that page's own items. While there are general notes every page shows its notes box (at the default spot until it's dragged; dragging one saves its place), but the PDF pack still only includes pages with pins or markup, each with its box. In the Items panel they're grouped under "General (every notes box)"; the editor has no kind switch, arrows or copies; delete and Undo work as for pins. Stored as an Item with `general: true`, drawingId "" and page 0.
- **Gesture model (GoodNotes style, decided in Spike B):** one finger scrolls, two fingers pinch to zoom. Scrolling is the browser's own (native scrolling): on iPad that is Safari's 120 Hz scrolling with iOS momentum and bounce, and on other platforms their own scrolling. At fit width (and below) the document is exactly as wide as the view, so it never moves sideways; zoomed in, it scrolls in any direction. A touch that lands while the document is scrolling only stops it; it never places a pin or opens one. Pinch is handled by the app (touch events, as in pdf.js's viewer): when the fingers go down, the app draws a screen-sized **snapshot** of the view (the pages' existing images, arrows, notes boxes and pins; a softer copy three views wide and high behind it for zooming out) and only that snapshot is scaled around the fingers (at most one update per frame, with page drawing paused); the document underneath doesn't move, so nothing is laid out or scrolled mid-gesture (Safari's separate scrolling would fight it, and reworking the huge zoomed-in layers every frame was measured at about 80 ms a frame on an iPad). When they lift, the new zoom is laid out once under the snapshot, which goes once the pages have redrawn and sharpened (at most 1.5 s), so that work happens while nothing on screen moves. Any new touch (a scroll or a tap) removes the snapshot at once. Pins scale with the picture during the pinch and return to their normal size after. Apple Pencil never scrolls the document. With a mouse, dragging pans, the wheel scrolls and ctrl+wheel (or a trackpad pinch) zooms. Android and Windows tablets should get their own native scrolling but are untested; pen handling there relies on the standard pen pointer type. **Placing pins (decided 2026-10-04, replacing "pins only via Add pin"):** finger, Apple Pencil and mouse all place pins. A **tap** on the drawing places an instruction pin at once (if an item's sheet or the Items/Drawings panel is open, the tap only closes that first); its sheet opens once a double-tap is no longer possible (350 ms), so it can't cover the spot of a second tap. A **double-tap** (second tap within 350 ms and 40 px; never treated as stopping a scroll) turns the pin the first tap placed into an observation, as part of the same undo step; a double-tap on an existing pin switches its kind (undoable). The pin turns blue as soon as the second press goes down, and its sheet opens when that finger lifts. **Double-tap and hold** (tap, then press again and hold) adds an arrow: the pin turns blue on the press, holding then dragging leaves the arrowhead on the spot and moves the pin to where the finger lifts (as for tap, hold and drag below), and the sheet opens on release, all in one undo step (on a pin that was already there it switches to observation and the pin stays put, its arrow pointing to where the finger lifts; if the first tap only closed a panel, a new observation is placed). **Tap, hold and drag:** after about 0.5 s without moving, a ring fills under the finger (it appears 150 ms into the press, so scrolls and pinches never show it) and a pin appears at the press point; the viewer then owns the touch (the document can't scroll). **Dragging leaves the arrowhead on the spot pressed and the pin follows the finger** (engineer, 2026-10-07: point at the thing first, then drag the pin to a clear place), kept on the same page; releasing places the pin there with its arrow back to the spot (one undo step), and releasing without dragging places just the pin at the press point. Moving before the hold completes scrolls as usual, and a second finger cancels it for a pinch. Tapping a pin opens it; dragging a pin moves it. The **Add pin** button in the tool pill stays as a fallback: tap it, then tap the drawing. **Slice 2 (section 5a):** these gestures apply only while the **Pin** tool is on, which replaces the Add pin button.
- **Pages view (decided 2026-10-04):** the page button (and **Pages** on the Pre-inspection Drawings card) opens every page of the document as thumbnails, GoodNotes style: numbered through the document, the drawing's name under its first page, a red pin count on pages with pins, the current page outlined, and a **+** tile to add drawings. Tapping a page goes to it. Each page's **⌄** menu: **Go to page**, **Duplicate** (a copy of the same sheet, without pins, right after it; later pages' pins and notes boxes move along and letters follow), **Hide** (not for pages with pins: remove their items first), **Move page earlier / later** (within its own drawing, past the next visible page, with its pins and notes box; a page can't move into another drawing), and with two or more drawings **Move drawing earlier / later** and **Reorder drawings…** (the drawings as a list; drag ≡ to move one). The menu stays open after a move so it can be repeated, and opens upward for pages low in the sheet. **Select** mode ticks pages for **Hide N pages**, **Duplicate**, or **Hide unmarked pages (N)**. Hidden pages are listed at the bottom with **Restore**; they leave the document, its page numbers and the PDF pack, and the original PDF never changes. Page changes aren't undoable (Restore and hiding a copy undo them; a move is undone by moving back).
- **Reordering (decided 2026-10-05):** drawings can be reordered (drag ≡ on the Pre-inspection Drawings card, or from the Pages view) and pages moved within their drawing. The document, page numbers, PDF pack and letters all follow the new order (re-lettered at once; the Export card warns if the memo was already exported). Drawing order is still `createdAt`: a reorder swaps the drawings' values, so new drawings go last.
- Fields per item: letter, kind, drawing + page, position, text, photos (0..n), `requiresPhotoConfirmation` (bool, only meaningful for instructions). No open/closed status in the POC (re-inspections are out of scope).

## 5a. Markup (slice 2; decided 2026-10-06; part 2a built 2026-10-06)

- **Toolbar (GoodNotes style):** a full-width white toolbar joined to the screen header, between it and the drawing. It never floats over the drawing (so it can't cover the notes box), and the drawing doesn't resize when tools change. Tools in order (engineer, 2026-10-06): **Pin**, **Pen**, **Eraser**, **Highlighter**, then a button per shape (line, arrow, rectangle, ellipse, revision cloud), **Text callout** and **Select**, then the **Draw with finger** toggle. The row is centred in the bar and re-centres as a tool's options appear (it scrolls sideways only if it is wider than the screen). Icons are Lucide in near-black `#111` with a slightly heavier stroke than the app's other icons. For Pen, Highlighter, Shapes and Text the bar then shows three weights (thin, medium, thick) and its colour slots (small swatches); Pin, Eraser and Select show a one-line hint there instead. The right-edge pills keep Page / Items, the camera, Undo, Redo and Fit page. (The engineer chose a top toolbar for markup over the earlier "Pencil tools on the right edge".)
- **Every tool is a toggle:** one is on at a time; tapping it again turns it off. A drawing opens with **no tool on**: fingers and Pencil scroll and zoom, tapping a pin opens it, and nothing is placed or drawn.
- **Pin tool** (replaces the Add pin button): while on, it shows red with a hint in the toolbar (no banner over the drawing, which would cover the notes box), and the pin gestures in section 5 apply (tap, double-tap, hold and drag, double-tap and hold), pin after pin, until it is turned off. With Pin off, taps never place pins.
- **Drawing input:** with a drawing tool on, the Apple Pencil draws and a finger scrolls and pinches; a resting palm is ignored. **Draw with finger** (off by default, remembered on the device, for people without a Pencil): one finger draws and two fingers scroll and zoom (moved by the app, so without iOS momentum).
- **Colours (GoodNotes style, revised 2026-10-06 after the iPad test):** each tool has a row of up to 10 colour slots in the toolbar (pen, shapes and text share one row; the highlighter has its own: fluoro yellow, green, pink and red to start, from a fluoro preset set (engineer, 2026-10-07: the pastel set looked muddy; older highlighter slots were reset once, pen slots kept)). Tap a slot to use it; the slot in use shows a small ⌄, and tapping it again opens its **Pen colour** (or **Highlighter colour**) panel: 12 preset colours and **Custom…** (the iPad colour picker) recolour that slot only, live, never adding one; **Add colour** puts a new slot at the end of the row and selects it (the slot you were on keeps its colour); **Remove** deletes the slot in use (one always stays). Each tool remembers its slot and weight. Colours saved by the first 2a build were reset to the defaults (its picker added a colour for every move).
- **Weights:** three presets plus a slider (tap the selected weight again), sized relative to the sheet like pins, so A1 and A3 print alike; medium matches a pin arrow's line (about 4 pt on A1). No Pencil pressure: lines are an even weight.
- **Shapes (2b, built 2026-10-06; engineer decisions):** each shape has its own toolbar button after the highlighter (line, arrow, rectangle, ellipse, revision cloud; engineer request, replacing one Shapes button with a list), a toggle like the other tools; the shapes share one colour slot and weight. Each is dragged out from where the Pencil goes down to where it lifts (less than a few pixels draws nothing); shapes have their own colour slot (on the pen's colour row) and weight. Lines and arrows go in any direction (no snapping). Arrowheads keep a pin arrow's proportions, scaled by the line weight. Rectangles and ellipses fill the dragged box; clouds run round it with bumps about ten line-widths across (they grow with the weight). Rectangles, ellipses and clouds are filled with their colour at 10%; with the **Eraser**, a tap inside a filled shape takes the fill off and leaves the outline (undoable), and rubbing over a shape's outline removes it. **Draw and hold (pen and highlighter; shapes added 2026-10-07, engineer decisions):** a stroke held still at its end for half a second becomes the shape it looks like (`src/features/markup/shapeRecognition.ts`). A **closed** stroke (its end back near its start) becomes a circle (if nearly round) or ellipse, a rectangle (a square if its sides are nearly equal; corners made right angles), a triangle, or a polygon through its corners; a shape drawn at an angle keeps its angle (within 4° of level it is made level); anything unclear stays as drawn. Any other held stroke becomes a straight line from where it started, whose end follows the Pencil in any direction until it lifts. The shape snaps as soon as it's recognised, before lifting; dragging on, still pressed, grows it (further from its centre than when it snapped) or shrinks it (nearer), keeping its proportions and angle (engineer, 2026-10-07). It is saved when the Pencil lifts, in the tool's colour and weight; one Undo takes the stroke away. Pen shapes are filled lightly like the shape tools; highlighter shapes are drawn like a highlight, never filled (`Markup.highlight`). Rectangles and ellipses are ordinary Rectangle and Ellipse shapes, turned by `rotation` when drawn at an angle (since 2026-10-07), so Select resizes and rotates them; triangles and other polygons are `polygon` marks (their corners). (`oval`, a tilted ellipse as centre and axis ends, was used by the first build and still draws.) No arrows from holds. Later: free-form clouds round an irregular outline, and resizing shapes (with Select, 2d).
- **Text callouts (2c, built 2026-10-06; gestures reworked the same day, engineer decisions):** the **Text** button (a callout icon: a box of text with a dog-leg arrow) comes after the shapes, with sizes **S / M / L** (M = the notes box text, 1.2% of the sheet's short side) in place of weights, a colour slot on the pen's row, and the hint "Tap for a text box · hold and drag for an arrow" (landscape only; in portrait the sizes and colours fill the bar). With Text on, callouts are placed like pins, with a finger or the Pencil: a **tap** places a box with no leader; **tap, hold (the ring fills, about 0.5 s) and drag** leaves the arrowhead on the spot pressed and drags the box out to where you lift (engineer, 2026-10-07, as for pins), the box hanging from its **corner nearest the arrowhead** there so it grows away from the arrow as you type (drag up and left and it grows up and left); lifting without dragging gives just the box, its top-left at the press; either way the keyboard opens and you type. A quick drag without the hold does nothing (a finger scrolls). A callout is a white box with a thin border in its colour and capitals in Arial on screen (Helvetica in the PDF); it grows as you type up to 24 letters' width, then wraps (a new line typed stays). **Leaders are dog legs** (drafting style): a short horizontal shoulder (1.5 letter heights) out of the middle of the box's side facing the tip, then straight to the tip; a tip above or below the box (within a shoulder of its sides) gets a straight line from the nearest edge. The leader is as thick as the box's border, its head in the arrow shape's proportions. Typing finishes when the box loses focus (tap elsewhere or change tool); left empty, it isn't kept. A tap on open space while typing closes the editor and **turns Text off altogether** (engineer, 2026-10-06: it kept starting new boxes), so each new callout starts from the Text button. **Tapping a callout** (whatever tool is on) **selects it and turns Text on**: a dashed outline and a width handle on its right side show, and every callout's arrow tip shows its small hollow handle. **A second tap edits it.** A tap on open space while one is selected lets it go and turns Text off again, back to the tool that was on before the callout was tapped (or none). Drag a callout's box to move it, its arrowhead to re-point it, and the selected one's side handle to **resize** it: the width is then kept (never narrower than its longest word) and the text re-wraps, the height following the text (`Markup.fixedWidth`). Each is undoable. Moving and re-pointing work with any tool and a finger or the Pencil (the box has a 14 px grab margin and the tip a 22 px grab circle); with Pen, Highlighter, a shape or the Eraser on, the Pencil draws over callouts instead; the eraser removes them like any mark. The box being typed is laid out at 16 px or more and scaled down, since iOS zooms into smaller text boxes. Stored as a Markup with tool `text`, `text`, the box's x, y, width and height then the tip as points, the size as its weight, and `fixedWidth` once resized. Pin arrows are dog legs too (section 5).
- **Eraser:** removes each whole mark it touches (no partial erasing).
- **Select (2d, built 2026-10-07; engineer decisions):** the **Select** button (a lasso with a dotted loop) comes after Text, with the hint "Tap a mark or draw a loop round several · tap open space to deselect". With the Pencil (or mouse, or a finger with Draw with finger), a tap picks the mark under it and a loop picks every mark with **any part** inside it; a finger's tap picks too, and a finger drag elsewhere scrolls. Pen strokes, highlights, shapes and text callouts can be picked; pins and the notes box can't. **Tap a mark to pick it (engineer, 2026-10-07):** with no tool on, or the Pen, Highlighter or a shape tool, a tap (finger or Pencil, no stroke) on a drawn mark picks it and turns Select on, so it can be resized, rotated or changed at once; with the Pen a tap on a mark no longer leaves a dot (a tap on blank paper still does). Letting go (a tap on open space) goes back to the tool that was on. Pin, Eraser and Text keep their own taps (a pin can still go on a cloud). **Callouts in Select (engineer, 2026-10-07):** a tap on the one picked callout opens it for typing without leaving Select (a tap elsewhere closes the editor), and one picked callout shows its arrow-tip handle (re-point) and side handle (width, kept from then on), as with the Text tool. The picked marks show a dashed box; dragging inside it (finger or Pencil) moves them all, kept on the page (a callout's arrow moves with it). One picked rectangle, ellipse or cloud shows eight handles to resize its box; a line or arrow shows a handle at each end. A **floating bar** (charcoal, screen-sized) sits above the box (below it near the top of the page) and hides while dragging: **Colour** (the pen row's slots and presets; recolouring a mixed selection leaves highlights their own colour, and with only highlights picked it offers the highlighter's colours), **thin / medium / thick** (each mark gets its own tool's preset; callouts keep their size unless only callouts are picked, when it shows S M L and their boxes follow), **Duplicate** (copies a little down and right, which become the selection) and **Delete**. A tap on open space lets go and Select stays on. Each move, resize, recolour, weight change, duplicate and delete is one Undo step. **Rotate (engineer, 2026-10-07):** a round handle on a stalk above the selection turns it, about its middle: a single rectangle, ellipse or cloud turns about its own centre (stored as `Markup.rotation`; its dashed outline and resize handles turn with it, and dragging a handle resizes it along its own sides, the far side staying put); several marks turn together as a group (strokes, lines, arrows and polygons by turning their points; box shapes by moving and turning; callouts move with the group but their text stays level; a lone callout has no rotate handle). Turns snap to level and 45° steps within 4°. One Undo step per turn. The floating bar sits above the rotate handle.
- **Pages and layering:** markup is drawn under the pins, arrows and notes box. Pages with markup can't be hidden (like pages with pins); duplicated pages start without markup.
- **Undo:** every mark, erase and edit is one Undo / Redo step in the existing history. **Two-finger double-tap** on the drawing undoes (GoodNotes style; engineer, 2026-10-07), whatever tool is on: two fingers tapped together twice within about half a second, without moving (a pinch or scroll never counts); a short note at the top of the drawing says what was undone ("Undo: Draw", or "Nothing to undo").
- **Export and file:** markup is burned into the PDF pack as vector, and pages with markup but no pins are exported too. The inspection file carries the markup records (`schemaVersion` 2); older files still import.
- **Built in parts:** 2a toolbar, Pin tool, pen, highlighter, eraser, finger toggle, palette and weights (with export, file and undo; built 2026-10-06, iPad plan docs/test-plans/slice2a-markup.md); 2b shapes; 2c text callouts; 2d select. Until 2b to 2d, the toolbar shows only the tools that are built.
- **How 2a draws (built; revised 2026-10-06 after iPad tests):** the stroke being drawn goes on a canvas over the viewer at the Pencil's full rate (coalesced samples), exactly through the points the Pencil reports, joined by straight lines, with no smoothing (the engineer wants the line to follow the tip exactly); **Pencil prediction** (Settings, Drawing; off by default) extends it toward the iPad's predicted points, never saved. The canvas exists only while drawing. When it lifts, the stroke is simplified to within a quarter of a screen pixel and saved. Saved marks drop points closer than a third of the line width to the last one kept (removing the sub-pixel wobble that made thick lines double back, which Apple's renderer drew with white crescents), get a light evening-out (each point averaged with its neighbours twice, ends fixed), and are drawn as straight segments as SVG in page units (`src/features/markup/markGeometry.ts`; the pinch snapshot and PDF draw the same path). Highlights are 55% see-through on screen (40% until 2026-10-07) and multiplied in the PDF. Painting marks into canvases instead (to stop slow scrolling on pages with markup) was tried and rolled back on 2026-10-06: zoomed pages stayed blurry on the iPad, cause not yet known; a diagnostics panel comes next, then scrolling and zoom are fixed together.
- **Diagnostics (step 10, built 2026-10-08):** Settings, Drawing (also in the Settings section list) **Show diagnostics** (off by default, kept on the device) shows a charcoal panel at the top left of the drawing, for the engineer to screenshot or **Copy** (as text) on the iPad, where there's no Web Inspector without a Mac. For each page on screen: its number and paper size (never the drawing's name), the base render's and the sharp render's detail (device pixels per PDF point) against what the view wanted, with the reason when cut back (the base image's 4 MP cap or the sharp render's 12 MP budget shared by the pages on screen), canvas megapixels and render time (green as wanted, amber cut back, red failed). Then all live canvases (count and megapixels), the marks on screen and their outline segments, the last scroll (length, frames per second, worst frame, and the share of it during which a page was being drawn), a page's quick preview while its base waits for scrolling to stop, a base image "kept from earlier", how long the PDF took to open and its size, and the last five render or PDF errors with their times. **Hide** folds it to a Diagnostics chip. It reads the numbers every half second and costs nothing while off (`src/features/drawings/document/diagnostics.ts`, `diagnosticsReport.ts`, `DiagnosticsPanel.tsx`). It comes first so the slow scrolling with lots of markup and the blurry zoom are fixed from device numbers, not guesses.

## 6. Photos

- **General photos** (not tied to a pin, e.g. overall views) are added in the Site memo step's Photos section, or with the **camera** button in the drawings toolbar (without leaving the drawing), with the same Take photo / Choose photos, viewer, captions, originals and Save to iPad as item photos (saved as `SY000001 General 1.jpg`). The Site memo step's Photos section shows every photo grouped as the appendix will be (instructions, observations, then General); it has no Undo button, so deleting a photo there asks first.
- Each item's sheet has a **Photos** section: **Take photo** opens the camera; **Choose photos** opens the library (several at once). Photos taken in the iPad's Camera app are saved to Photos automatically and can be added with Choose photos.
- Photos attach to an item and also appear in the **photo appendix** at the end of the PDF pack, grouped by item (e.g. Instruction A) with captions. Captions are optional; a photo without one shows none.
- Every photo gets a **working copy**: JPEG, long edge 1600 px (never enlarged), quality 0.8, the right way up. The camera stores which way up as an EXIF flag; Safari and Chrome apply it when decoding, and the working copy has no EXIF, so it can't be rotated twice. Photos are decoded one at a time to stay within iPad memory.
- **Camera shots also keep their full-size original**, so they can be saved to the iPad at native resolution later. Library picks keep only the working copy (they are already in Photos). Originals use roughly 3–5 MB each.
- Thumbnails in the sheet open a full-screen viewer on the app's cream background, kept clear of the iPad's status bar and home bar: swipe sideways (or use the arrow keys) between photos (the photos either side are preloaded in a strip that follows the finger and glides on release; a quarter-width drag or a quick flick changes photo), an optional caption (saved as you type, when moving on, and by **Save** at the top, which also closes the viewer; **Close** keeps it too) and Delete. Adding and deleting photos are undoable. The Items lists show each item's photo count.
- **Save to iPad** (item sheet, that item's photos) and **Save photos to iPad** (Site memo step, every photo, in item list order) share the photos through the Share sheet: choose Save Images (Photos) or Save to Files. A web app can't save to Photos silently; iPadOS only allows the Share sheet straight after a tap, so each batch of up to 20 is loaded first and shared on the next tap. Camera shots are shared as their original, others as the working copy, named like `SY000001 Instruction A 1.jpg`. Browsers without file sharing download the files instead.
- **Free up space** (Site memo step) removes the full-size originals of photos already saved to the iPad; the working copies stay for the report.
- Storage is the main offline risk on iPad (see section 10).

## 7. PDF export pack

One PDF, in this order:
1. Memo page(s) (branded, A4).
2. Marked-up drawing page(s): only the pages that have pins, in document order (hidden pages are left out; a duplicated page with pins is its own page, a copy of the same PDF page). Each is the original PDF page copied in as it is (vector, not redrawn), with the pins, arrows and notes box burned in at the same size and place as in the viewer (shared geometry in `src/features/drawings/observationBox.ts` and `arrows.ts`; Helvetica). **Each page keeps its native size** (the PDF will mix an A4 memo with larger drawing sheets). Pins are sized to the sheet: 1.6% of its short side across, about 9.5 mm on A1, 4.8 mm on A3 and 3.4 mm on A4 (engineer decision, 2026-10-04); on screen they stay a fixed size. Sheets saved rotated or cropped keep their pins where the viewer shows them. Drawing pages get no Northrop footer (they have their own title block). Watch file size and test with real large drawings.
3. Photo appendix (engineer decisions, 2026-10-02): A4 pages, **4 photos per page** (2 × 2), using the working copies. Groups in this order: **instructions** A, B, C… (matching the memo's conditions), then **observations** A, B, C…, then **General** last. Each group is headed by the item's label and text, e.g. "Instruction A – Add N12 bar at grid C/4" ("General" for general photos). Each photo is labelled **Photo IA1**, IA2… (instruction A), **OA1**… (observation A) or **G1**… (general), followed by its caption if one was typed, just under the photo. Photos are fitted into their cell (never cropped), left-aligned; each group starts a new row, and a group carried onto the next page repeats its heading with "(continued)". The top of each page shows the memo reference and item inspected, and "Photo appendix".

The memo and appendix pages carry the memo's footer, numbered through the whole pack (drawing pages count but aren't stamped).

Export must work offline. It runs on the device (pdf-lib), reading drawings and photos one at a time.

### 7a. Memo reference and filename

- Reference format `SIM-NNN`, counted per job number, generated when the memo is created and editable afterwards.
- Because there is no sync, two devices could both create `SIM-002` for the same job. Mitigation for the POC: memos are created on the iPad, desktop is for editing imported inspections, and the reference stays editable. Flag this for the sync phase.
- Exported filename: `{jobNumber}_{reference}_{itemInspected}.pdf` (sanitised).

## 8. Data model

Stored locally in IndexedDB. File bytes (PDFs, photos) are stored in a `blobs` table as ArrayBuffer records `{ id, data, type, size }` and referenced by id. (Not Blob objects: Blob storage in IndexedDB is not supported by every WebKit build.)

```ts
Project        { id, jobNumber, jobName, client{ name, company, address1, address2 },
                 contacts[]: { id, company, attn }, createdAt, updatedAt }
               // a job: its details are shared by all its inspections and their memos
Inspection     { id, projectId|null, itemInspected, date, inspector, status, backedUpAt?,
                 photoIds[],   // general photos (not tied to a pin)
                 unsorted?{ jobName, client },   // details from before projects, when it had no job number
                 createdAt, updatedAt }
               // projectId null: "Needs a project" (no memo until it has one)
Drawing        { id, inspectionId, name, pdfBlobId, pageCount, pages[], fileSize, pageSizes, createdAt }
               // name defaults to the file name; pageSizes [w, h] per PDF page lay out the document;
               // pages[] { source, hidden? }: the drawing's pages in order (each PDF page to start;
               //   duplicates repeat a source, hidden ones leave the document); Item.page and
               //   ObservationBox.page are 1-based positions in it (Dexie v11);
               // createdAt orders drawings in the document (reordering swaps the values)
Item           { id, inspectionId, letter, kind: 'instruction' | 'observation', general?,
                 drawingId, page, x, y,   // x,y normalised 0..1 of page
                 text, requiresPhotoConfirmation, photoIds[], createdAt,
                 sequence,    // order on its page: placement order unless reordered
                 arrows[],    // { id, x, y }: arrow tips, normalised 0..1 on the item's page
                 copies?[] }  // Copy pin: { id, drawingId, page, x, y, arrows[] } more spots of the same item
Photo          { id, blobId, originalBlobId?, originalSize?, source: 'camera' | 'library',
                 caption?, takenAt, width, height, savedAt? }
               // blobId: working copy (1600 px JPEG); originalBlobId: camera original, until freed
Memo           { id, inspectionId, templateId, reference, recipients[], siteVisitRequestedBy|null,
                 reasonForVisit|null, sentVia, salutation|null, bodySnippetId, bodyText,
                 conditionChoices{snippetId: bool}, itemOverrides{itemId: text},
                 signOffName, signOffTitle, signatureBlobId|null, includeSignature,
                 exportedAt?, exportedLetters?{itemId: 'kind:letter'},
                 createdAt, updatedAt }
               // one per inspection; job details (client, address, date, job number/name,
               // item inspected, inspector) are read from the inspection, never copied; null = default.
               // The signature is the memo's own copy (PNG in blobs), so it travels with the inspection.
               // exportedAt / exportedLetters: the last PDF pack export and each item's letter then
               // (warns when letters change before sending)
MemoCounter    { jobNumber, lastSeq }   // drives SIM-001, SIM-002 ... per job number
MemoTemplate   { id, name, branding{ colours, logoBlobId, fonts }, fixedText{ disclaimer, officeBlock } }
               // POC: a single hard-coded Northrop template (see section 4a)
ObservationBox { id, drawingId, page, x, y }   // normalised 0..1 top-left; one per drawing page with pins
Snippet        { id, kind: 'body' | 'condition' | 'heading', label, text }   // 'heading' = observations box heading
Markup         { id, inspectionId, drawingId, page, tool, points[], colour, weight, fill?, highlight?, rotation?, text?, fixedWidth?, createdAt }
PageImage      { id: `${drawingId}:${source}:${width}x${height}`, drawingId, source, width, height, data (PNG), size, createdAt }
               // step 10b: a page's saved base image (Dexie v13); a cache, never in inspection files
               // slice 2 (section 5a): one record per mark; points normalised 0..1 of the page;
               // weight relative to the sheet's short side; page is a position in Drawing.pages
Settings       { inspectorName, inspectorTitle, defaultSentVia, signatureBlobId?, ... }
               // signatureBlobId: my signature (PNG), copied into each new memo
// later
Calculation    { id, type, inputs, outputs, createdAt }   // standalone history, no inspectionId, never exported with an inspection
```

Pin coordinates are stored relative to the page (0..1), so they stay correct at any zoom, device, or export resolution.

## 9. Inspection file (move between devices)

A single zip with the extension `.inspection` (built step 9, 2026-10-05), named `{jobNumber}_{itemInspected}_{YYYY-MM-DD}.inspection`, containing:
- `inspection.json`: `schemaVersion` (1), the app build that wrote it, when, and the records for that inspection: its project, the inspection, drawings (with their `pages` lists), items (with arrows and copies), notes boxes, photo records, the memo (with its export record) and the prefilled messages (snippets).
- `drawings/` the original PDFs, `photos/` the working copies, `originals/` the full-size camera photos (only when **Include full-size camera photos** is on; off by default, since they're saved to Photos with Save to iPad), `signature/` the memo's signature.

Zipped with fflate (bundled; works offline); PDFs and photos are stored as they are. Export then import is round-trip tested. Saved page images (section 12) are not included; the importing device remakes them.

**Import** (Inspections page, **Import inspection…**, any file from Files): shows what the file holds (project, drawings and pages, pins, photos, memo), then:
- never silently overwrites: if the same inspection is already on the device it asks **Replace** (in one step, so a failed import leaves the old copy) or **Keep both** (the file's copy gets new ids);
- the project: if it's already here (same id, else the same job number, ignoring case and spaces) the inspection joins it and the device's project details are kept; otherwise the file's project is added;
- prefilled messages the device doesn't have are added (existing ones are left alone);
- the job's memo counter moves up to the memo's SIM number, so references aren't reused;
- a file from a newer app version is refused with a message to update; anything else gets "This isn't an inspection file." Desktop uses the same app and its own local storage: import, edit, export PDF, optionally export the file back.

## 10. Offline and storage

- Service worker precaches the app shell; the app loads and works with no connection.
- Request **persistent storage** (`navigator.storage.persist()`) on first run.
- Show a storage meter and a clear **Back up now** action (exports the inspection file). Built step 9: each inspection's Pre-inspection step has a **Backup** card ("Not backed up yet", "Backed up" or "Changed since last backup" with the time; **Back up now** builds the file, then **Share…** opens the Share sheet, Save to Files; a desktop downloads it). It counts as backed up once the file is shared or saved (`Inspection.backedUpAt`); any edit after that (pins, photos, memo, drawings, job details) makes it "changed". Settings, **Storage and backup** has **Back up all** (one file per inspection, working copies only, shared together). The Dashboard's Needs attention tile lists inspections with drawings or items that aren't backed up, linking to their Pre-inspection.
- **Removing the app from the Home Screen deletes its data** (a home-screen web app has its own storage). Settings, Storage and backup opens with a warning not to remove Hardhat from the Home Screen and to back up first (engineer, 2026-10-07).
- iOS may evict a web app's stored data if it is unused for a long time. Mitigations: home-screen install, persistent storage request, prominent backup prompt after each inspection.
- Never store anything only in memory.
- Saved page images (section 12) are a cache: about 1–3 MB per A1 sheet, shown in the storage meter's total, removed with their drawing.

Saved images are per page and size (rotating the iPad can save a second set), roughly 1–3 MB per A1 sheet (in the storage meter's total), never in inspection files (an imported inspection's are remade) and tidied away at start-up and when the drawings open once their drawing is gone (`src/features/drawings/document/savedPages.ts`, `src/db/pageImages.ts`). **Sharp when zoomed:** 0.6 s after the view settles (0.15 s when drawing in the background, below), the view and a margin (up to half a view each side, within a 12 MP budget shared by the pages on screen; the margin shrinks before the detail does) are drawn in **one** drawing from the PDF's vectors at full screen detail, and kept while they still cover the view at the right detail, so small scrolls and pans redraw nothing. **Drawing ahead (engineer, 2026-10-14: usually a screen or so round one spot):** when drawing in the background, the areas round that drawing are then drawn too at the same zoom, sides then corners, out to one view beyond the view, and kept (up to 40 MP shared by the pages on screen; the furthest go first, and images at another zoom go once the view is sharp at the new one), so a scroll nearby is sharp at once; each is one drawing the size of the view's own, about 2 s each on the B1. Background drawings carry on while the document moves; on the main thread they stop. Diagnostics show the images kept (`useSharpImages.ts`). (Drawing in pieces was tried: pdf.js works through the whole page for every piece, 13 s on the B1, so it was removed, as were a low-detail preview while scrolling and a memory cache of recent pages, which saved images made redundant.) **True screen size (engineer, 2026-10-13):** inside the magnified page Safari shows content from a lower-resolution copy, so the sharp image is laid out at its own pixel size and scaled back into place, on its own layer (compared live on the iPad: only this was crisp). The markup gets the same: when zoomed in and still, a display-only copy of the page's overlay (marks, callouts, notes box, arrows: the same SVG and text, still vector) is laid over the view and a margin at true screen size, and the original stays in place invisible but touchable, so taps and drags work as before; touching the page, moving it or typing in a callout shows the original (softer) until it settles, and the copy follows any change. Stored marks and the exported PDF are unchanged (vector). **Background drawing (2026-10-14; proven on the iPad first in the drawing lab (now under Settings, Developer): the B1 page froze the screen for 1.4 s on the main thread, one frame in the background, same picture):** one long-lived worker (`drawingWorker.ts`, used through `pageDrawer.ts`) runs its own pdf.js, keeps each open drawing's PDF and draws base images, sharp images and the pages saved ahead onto off-screen canvases, handing back finished pictures and the PNGs to save (encoded there too); stopping a drawing is heard between its steps. The queue, the 0.6 s delay and the on-screen-first order are unchanged. It draws fonts as shapes and skips SVG filters (rare in drawings; the engineer saw no difference). Where the browser can't draw off screen (before iPadOS 16.4), or a drawing fails there, pages are drawn on the main thread as before; the diagnostics panel says which ("Drawing on the background"), and its drawing line gives the longest the screen went without a new frame and the longest the main thread was held up, over the last stretch with PDF drawing, leaving out time the app wasn't on screen. The drawing lab also times two areas drawn by one background drawer after each other and by two at once (whether a second drawer would help). Paper sizes name ISO B sizes as well as A (B0–B4), e.g. "B1 (1000 × 707 mm)". It is the Inspection step; ?drawing= and ?item= links open it at a drawing or pin. An **Items** button opens a panel listing every item: observations, then instructions, each in letter order and grouped under a page subheading numbered through the document (e.g. "Page 4"); rows show just the letter and text, in one list split by hairlines. Rows whose pins are on screen are highlighted (a faint tint with a dark left edge), updating when scrolling or zooming pauses. Tapping one scrolls to its pin and opens its sheet. Swiping a row left shows a **Delete** button (deletes at once, undoable). Items of the same kind on the same page have a drag handle (≡) to reorder them, which re-letters them and reorders the notes box; reordering across pages isn't possible because letters follow the document. **Select** ticks several items: **Delete N**, **Make observations**, **Make instructions**, **Photo confirmation on / off** (instructions only), each one Undo step; swiping and dragging pause while selecting. **Undo** and **Redo** buttons (arrow icons) in the toolbar reverse and re-apply the latest pin added (with its arrow when placed by a hold and drag), item deleted, kind switched, reorder, or arrow added, moved or removed (undoing an add removes the pin with anything typed since, and its notes box if it was the page's first pin); doing something new clears Redo. ## 13. Build order

1. Project scaffold, PWA, offline shell, Dexie schema, deploy a "hello" to a shareable URL.

## 14. Risks

| Risk | Mitigation |
|---|---|
| PDF export fidelity on iPad Safari | Build PDF with pdf-lib, spike early |
| Large drawings (A1, many MB) slow on iPad | Render at device resolution only, lazy-render pages, test with real drawings early |
| iOS storage eviction / limits | Persistent storage request, storage meter, backup prompts |
| Pencil/touch gesture conflicts (pan vs draw) | Decided: one finger scrolls, two pinch; pins are placed only while the Pin tool is on, and markup only while a drawing tool is on (section 5a) |
| Calculator correctness (later) | Every formula cites its AS 3600 clause, has unit tests against hand calcs, and is verified by the engineer before use |
| Company data and AI tool policy | Check policy before using real drawings or client data with any AI tool |
